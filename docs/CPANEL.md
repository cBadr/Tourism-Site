> دليل عملي خطوة بخطوة، مكتوب لمن لم يشغّل Node على استضافة من قبل.
> اقرأ القسم (٠) كاملاً قبل أن تفتح cPanel — فيه ثلاث حقائق تقرر نجاح التجربة
> قبل أن تبدأ، وواحدة منها تعني أنك قد تسحب مشروعاً ناقصاً بلا أن تدري.
>
> **وهذه تجربة تشغيل لا نشر.** قرار تأجيل الدومين والنشر التجاري باقٍ كما هو
> (‏`handover/DECISIONS.md` ← D-35)؛ ما هنا نطاقٌ فرعي مؤقت ترى فيه المشروع
> يعمل على خادم حقيقي، لا إطلاقاً للعلامة.

## ٠) اقرأ هذا أولاً

### الحقيقة الأولى: ما على GitHub الآن **متأخر سبعة إصدارات**

المستودع البعيد المضبوط في مشروعك هو:

```
https://github.com/cBadr/Tourism-Site.git
```

الاسم قديم لكنه **مستودع هذا المشروع فعلاً** — تحققتُ من تاريخه: آخر ما وصله هو
`chore(env): add AI provider key placeholders for phase 11`.

ومعنى ذلك أن السحب اليوم يعطيك المشروع **بلا**:

| ما ينقص النسخة البعيدة | حجمه |
|---|---|
| المرحلة ١٢أ — الكوبونات والخصومات | هجرة `0024` |
| بذرة الستة أشهر التجريبية | `scripts/demo-seed.mjs` |
| تصليب ما يبلغه `authenticated` | هجرة `0025` |
| الدفعة ١ — تطبيع الهاتف والنسخ الاحتياطي والسيو | هجرة `0026` |
| الدفعة ٢ — المهلة والإيصالات وسقف الديون ومتابعة الحجز | هجرتا `0027` و`0028` |

فالخطوة الأولى في هذا الدليل هي **الدفع إلى GitHub** (القسم ٣) — وهي بأمرك أنت،
لأن الدفع لا يقع في هذا المشروع إلا حين تطلبه.

### الحقيقة الثانية: cPanel ليس الهدف الذي بُني له المشروع — وصالح للتجربة

المشروع مكتوب لخادم Node دائم، ومعه ملف `vercel.json` يجدول مهمتين. وcPanel
يستطيع تشغيل Node عبر «Setup Node.js App»، فالتجربة ممكنة — **وفيها مكسب حقيقي
واحد:** جدولة cPanel (cron) تحل محل جدولة Vercel وتعمل اليوم بلا انتظار نشر.

### الحقيقة الثالثة: شرطان بلا ثالث

1. **Node ‏٢٠٫٩ فأعلى.** هذا شرط Next نفسه (‏`next/package.json` ← `engines.node: >=20.9.0`).
   إن كان أعلى ما تعرضه استضافتك ١٨ فالبناء يفشل، ولا حيلة في ذلك.
2. **وجود «Setup Node.js App»** في لوحة cPanel (يعني CloudLinux + Passenger).
   إن لم تجدها فاستضافتك لا تشغّل Node أصلاً — والتجربة تتوقف هنا.

**افحص الاثنين قبل أي خطوة أخرى.** دقيقتان توفران ساعة.

## ٤) اسحب النسخة على cPanel

### الطريقة (أ) — من واجهة cPanel: Git™ Version Control

1. cPanel ← **Git Version Control** ← **Create**.
2. فعّل **Clone a Repository**.
3. **Clone URL:** رابط المستودع. وللمستودع الخاص تحتاج توثيقاً — أسهله رابط بصيغة
   `https://<TOKEN>@github.com/cBadr/Tourism-Site.git` بعد إنشاء **Personal Access
   Token** من GitHub بصلاحية `repo` وحدها.
   ⚠ التوكن يُحفظ في إعدادات cPanel — عامله كأنه كلمة مرور، وألغِه بعد التجربة.
4. **Repository Path:** ‏`/home/<اسم المستخدم>/apps/tours`
   **ليس داخل `public_html`** — لا نريد أن يخدم الخادم كود المشروع كملفات.
5. اضغط **Create**. وللتحديث لاحقاً: نفس الشاشة ← **Manage** ← **Update from Remote**.

### الطريقة (ب) — عبر SSH

```bash
mkdir -p ~/apps && cd ~/apps
git clone https://github.com/cBadr/Tourism-Site.git tours
cd tours && git log --oneline -1
```

آخر سطر يجب أن يطبع إصدار الدفعة ٢. إن طبع «phase 11» فأنت لم تدفع (القسم ٣).

## ٥) البيئة — أخطر قسم في هذا الدليل

أنشئ `.env.local` **على الخادم** داخل `~/apps/tours` (File Manager ← New File، أو
`nano .env.local` عبر SSH). لا يأتي هذا الملف من git أبداً.

انسخ القيم من `.env.local` عندك محلياً، ثم انتبه لهذه الخمسة:

| المتغيّر | القيمة | لماذا هنا تحديداً |
|---|---|---|
| `DATABASE_URL` | **صيغة Session pooler** من Supabase (‏Connect ← Session pooler) | المضيف المباشر **IPv6 فقط**، والاستضافة المشتركة IPv4 — فتفشل الهجرات والاختبارات بـ `ENOTFOUND`. هذه أشهر عثرة في المشروع كله |
| `SITE_URL` | `https://try.yourdomain.com` بلا شرطة في آخره | منه تُبنى الروابط القانونية وخريطة الموقع وبطاقات المشاركة. بدونه يظن الموقع نفسه على `localhost:3000` |
| `NOTIFY_DISPATCH_KEY` | سرّ تخترعه أنت | بدونه **تُقفل** المهام المجدولة في الإنتاج (تفشل مغلقة عمداً). ولّده: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` | كما هي محلياً | ⚠ **تُخبز داخل الحزمة وقت البناء لا وقت التشغيل.** فيجب أن تكون موجودة **قبل** أمر البناء، وإلا خرج موقع لا يعرف قاعدته وإصلاحه إعادة بناء لا إعادة تشغيل |
| `ALLOW_TEST_PAYMENTS` | **لا تضبطه إطلاقاً** | هو الحارس الثاني لبوابة الدفع التجريبية. ضبطه على موقع مفتوح = زرّ «أكّد حجزي مجاناً» يقيّد إيراداً وهمياً ويطلق البث |

وأضف سطراً لا وجود له في تشغيلك المحلي (لأن `pnpm dev` يضبطه بنفسه):

```
NODE_OPTIONS=--max-http-header-size=65536
```

بدونه يعود خطأ **HTTP 431** فجأة بعد أن تتراكم كوكيز الجلسة — وهو الخطأ الذي كلّف
هذا المشروع ساعات مرة سابقة.

> **قاعدة:** كل ما سبق أسرار. لا تضعها في مستودع ولا في تذكرة ولا في محادثة.

## ٦) التثبيت والبناء

### تفعيل بيئة Node الصحيحة (SSH)

بعد إنشاء التطبيق في القسم (٧)، تعطيك cPanel أمر تفعيل يشبه:

```bash
source /home/<user>/nodevenv/apps/tours/20/bin/activate && cd /home/<user>/apps/tours
```

**شغّله قبل أي `npm` أو `pnpm`** وإلا استعملت نسخة Node الخاطئة. وللتأكد:

```bash
node -v      # يجب أن يبدأ بـ v20 أو أعلى
```

### مدير الحزم

المشروع يستعمل **pnpm** (‏`pnpm-lock.yaml`). جرّب:

```bash
corepack enable && corepack prepare pnpm@latest --activate
pnpm install --frozen-lockfile
```

وإن مُنع `corepack` على الاستضافة:

```bash
npm install -g pnpm && pnpm install --frozen-lockfile
```

وإن تعذّر الاثنان فـ `npm install` يعمل — **مع تحفّظ مكتوب**: يتجاهل قفل pnpm فقد
يركّب إصدارات أدق اختلافاً عمّا اختُبر عليه المشروع.

### البناء

```bash
BUILD_STANDALONE=1 pnpm build
```

`BUILD_STANDALONE=1` مفتاح خامل افتراضياً أُضيف لأجل هذه الحالة تحديداً
(`next.config.ts`): يجعل Next يُخرج خادمه الإنتاجي المصغّر في
`.next/standalone/server.js` ومعه ما يلزمه من `node_modules` — وهو **خادم Next
نفسه**، فيعمل `proxy.ts` بلا أي إعداد إضافي (نصّ دليل Next: «Proxy works
self-hosted with zero configuration when deploying using `next start`»).

ثم **انسخ ما لا ينسخه المخرج المصغّر بنفسه** — وهذه خطوة يسهل نسيانها ونتيجتها
موقع بلا تنسيق ولا صور:

```bash
cp -r public .next/standalone/
cp -r .next/static .next/standalone/.next/
```

> **إن قُتل البناء** ورأيت `Killed` أو خروجاً بالرمز `137`: ذاكرة الاستضافة لم
> تكفِ. لا تكرّر المحاولة — الحل: **ابنِ على جهازك** بنفس الأمر، ثم ارفع مجلد
> `.next` (المضغوط) إلى `~/apps/tours` عبر File Manager. البناء المحلي والخادمي
> متكافئان ما دامت متغيّرات `NEXT_PUBLIC_*` واحدة.

## ٧) تشغيل التطبيق

cPanel ← **Setup Node.js App** ← **Create Application**:

| الحقل | القيمة |
|---|---|
| Node.js version | ٢٠٫٩ أو أعلى |
| Application mode | **Production** |
| Application root | `apps/tours` |
| Application URL | النطاق الفرعي `try.yourdomain.com` |
| Application startup file | `.next/standalone/server.js` |

ثم في **Environment variables** أضف — من الواجهة لا من الملف:

```
NODE_ENV=production
NODE_OPTIONS=--max-http-header-size=65536
```

> Passenger يشغّل الملف مباشرةً ولا يمر بـ `pnpm start`، فمتغيّرات `package.json`
> لا تصل إليه. ولهذا يُضبط `NODE_OPTIONS` هنا **أيضاً**.
>
> ولا حاجة لضبط `PORT`: يضبطه Passenger بنفسه ويقرؤه خادم Next.

اضغط **Restart**، ثم افتح النطاق الفرعي.

**لإعادة التشغيل بعد أي تحديث لاحق:** زر Restart في نفس الشاشة، أو عبر SSH:

```bash
mkdir -p ~/apps/tours/tmp && touch ~/apps/tours/tmp/restart.txt
```

### إن تعثّر Passenger — الخطة البديلة

شغّل خادم Next على منفذ ثم مرّر إليه الطلبات من Apache:

```bash
PORT=3001 pnpm start &
```

ثم في `public_html/<subdomain>/.htaccess`:

```apache
RewriteEngine On
RewriteRule ^(.*)$ http://127.0.0.1:3001/$1 [P,L]
```

⚠ كثير من الاستضافات المشتركة **تمنع** `mod_proxy` وتمنع العمليات الطويلة. إن
رفضت، فالخطة البديلة ساقطة عندك وليست خطأً منك — عد إلى Passenger أو غيّر الاستضافة.

**لا، إن كنت تستعمل نفس قاعدة Supabase** التي تعمل عليها محلياً — القاعدة واحدة


## ٩) الجدولة — cron في cPanel بدل `vercel.json`

هذا ما لا يعمل اليوم عندك أصلاً، ويعمل على cPanel فوراً. المهمتان في `vercel.json`
تصيران مهمتَي cron:

cPanel ← **Cron Jobs** ← أضف مهمتين (استبدل `SECRET` بقيمة `NOTIFY_DISPATCH_KEY`):

**كل دقيقة — عامل الإشعارات:**

```
* * * * * curl -fsS -H "x-dispatch-key: SECRET" "https://try.yourdomain.com/api/notifications/dispatch?run=1" >/dev/null 2>&1
```

**كل خمس دقائق — دورة البث (ومعها كنس الطلبات غير المدفوعة):**

```
*/5 * * * * curl -fsS -H "x-dispatch-key: SECRET" "https://try.yourdomain.com/api/dispatch/tick?run=1" >/dev/null 2>&1
```

> المسار الثاني يشغّل أيضاً كنس الطلبات غير المدفوعة (الدفعة ٢) — فلا مهمة ثالثة.
> والكنس **مطفأ افتراضياً** حتى تفعّله من `/admin/settings` ← إعدادات الرحلات.

**للتأكد أنها تعمل:** احذف الترويسة مؤقتاً وشغّل الأمر يدوياً — يجب أن يرد `401`.
ثم أعدها — يجب أن يرد `200` بملخّص. الرد `401` مع الترويسة يعني أن السرّ في cron
يخالف الذي في البيئة.

## ١٠) قبل أن تفتحه لأي أحد — خمسة بنود

1. **امنع الفهرسة.** نسخةٌ ثانية من نفس المحتوى على نطاق آخر تُنافس نطاقك الحقيقي
   لاحقاً. في `public_html/<subdomain>/.htaccess`:


2. **`ALLOW_TEST_PAYMENTS` غير مضبوط** — تأكد بعينك من قائمة متغيّرات البيئة.
3. **HTTPS مفعّل** (cPanel ← SSL/TLS Status ← Run AutoSSL). كوكي الجلسة عبر HTTP
   يجعل دخول اللوحة يدور في حلقة.
4. **كلمة مرور اللوحة قوية** — الموقع صار على الإنترنت المفتوح، والحساب
   `cbadrx100@gmail.com` هو الباب.
5. **البيانات التجريبية.** إن استعملت قاعدتك الحالية فالموقع يعرض بيانات ستة أشهر
   محاكاة وحجوزات حقيقية التجربة. لا تشارك الرابط مع من لا تريده أن يراها.

## ١١) أعطال متوقعة وعلاجها

| العَرَض | السبب | العلاج |
|---|---|---|
| `HTTP 431` بعد تصفح قليل | `NODE_OPTIONS` غير مضبوط في بيئة التطبيق | أضفه في Setup Node.js App ثم Restart |
| فشل الاتصال بالقاعدة · `ENOTFOUND` | `DATABASE_URL` بصيغة المضيف المباشر (IPv6) | استبدله بصيغة **Session pooler** |
| `Invalid Server Actions request` عند حفظ أي نموذج | الوكيل العكسي يغيّر `Origin` عن `Host` | أضف `SERVER_ACTION_ORIGINS=try.yourdomain.com` ثم **أعد البناء** |
| الصفحة بلا تنسيق، وملفات `/_next/static` ‏٤٠٤ | نُسي نسخ `public` و`.next/static` إلى `standalone` | أعد أمرَي `cp` في القسم ٦ ثم Restart |
| `Killed` أو خروج `137` أثناء البناء | ذاكرة الاستضافة | ابنِ محلياً وارفع `.next` |
| الصور لا تظهر أو الذاكرة تنفجر عند فتحها | `sharp` أو حدود الذاكرة على glibc | في `next.config.ts` أضف مؤقتاً `images: { unoptimized: true }` وأعد البناء |
| 503 من Passenger عند الفتح | الملف الابتدائي خطأ أو Node أقدم من ٢٠٫٩ | راجع سطر Application startup file، وسجل الأخطاء في `~/apps/tours/stderr.log` |
| تعديلاتك لا تظهر | لم يُعد البناء أو لم يُعد التشغيل | `git pull` ← `pnpm install` ← `BUILD_STANDALONE=1 pnpm build` ← نسخ ← Restart |
| الموقع يظن نفسه على `localhost` في الروابط | `SITE_URL` غير مضبوط | اضبطه **وأعد البناء** |
| `401` من مهام cron | السرّ في cron يخالف البيئة | وحّدهما وأعد التشغيل |

2. احذف مهمتَي cron.
3. احذف `~/apps/tours` بالكامل (وفيه `.env.local` بأسرارك).
4. احذف النطاق الفرعي.
5. **ألغِ Personal Access Token** من GitHub إن أنشأته للسحب.
6. إن استعملت قاعدة تجربة منفصلة، احذف مشروع Supabase.
