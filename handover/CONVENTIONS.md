## ١) العربية والاتجاه والنبرة

| القاعدة | السبب في سطر |
|---|---|
| العربية لغة الأصل: `app/layout.tsx` يضبط `lang`/`dir` من اللغة الفعّالة، والعربية `rtl` والخط Cairo | الجمهور المستهدف عربي، والـ RTL ليس زخرفة بل بنية تخطيط كاملة |
| **الروابط العربية بلا بادئة لغة إطلاقاً** — `/book` لا `/ar/book`؛ و`/ar/...` و`/EN/...` و`/en/x/` كلها ٣٠٨ إلى شكلها الوحيد (`proxy.ts:126-135`) | عنوان واحد لكل صفحة، فلا ينقسم وزنها في نتائج البحث — والسيو هو المنتج نفسه |
| استعمل الخصائص المنطقية في Tailwind: `start/end` و`ms/me` و`ps/pe` لا `left/right` | كي يبقى نفس المكوّن سليماً في LTR بعد تفعيل الإنجليزية |
| تعليقات الكود وتعليقات SQL ورسائل الأخطاء **بالعربية** | القارئ الأول هو بدر، والمساعد التالي يفهم النية لا الآلية فقط |
| نبرة النصوص: مباشرة، بلا مبالغات تسويقية، ورسالة الخطأ تقول ماذا يفعل المستخدم الآن | «حدث خطأ» تُرجع المستخدم إلى الصفر؛ الرسائل في المستودع تشرح السبب والخطوة |

| الأرقام العربية الهندية تُقبل في الحقول الرقمية وتُحوَّل قبل التحقق (`toLatinDigits` في `app/admin/pricing/actions.ts:33`) | لوحة مفاتيح المستخدم العربي تنتج `٠-٩` فيفشل `Number()` بلا سبب مفهوم |

## ٢) كل حساب مالي في Postgres — بلا استثناء

| القاعدة | السبب في سطر |
|---|---|
| السعر والتكلفة والهامش والذروة والأرصدة وكشوف الحساب: **دوال وviews في Postgres** (`quote_price`, `quote_public`, `ledger_entries` ومشتقاتها) | مصدر واحد للحقيقة يخدم الموقع العام واللوحة والبورتال والوكيل لاحقاً؛ حسابان في مكانين ينحرفان حتماً |
| TypeScript **يعرض ويُنسّق فقط** — لا جمع ولا ضرب ولا تقريب مالي (`components/booking/format.ts` تنسيق محض) | أي حساب في الواجهة يصبح رقماً ثانياً لا يطابق كشف الحساب |
| الدفتر `ledger_entries` **append-only**؛ العكس قيد مقابل (`reverse_ledger_entry`) لا حذف | تاريخ مالي محذوف لا يُدقَّق ولا يُصالح |

| `net_due = earned − collected − paid` **وقد يكون سالباً** (المتعهد مدين لنا) — كل شاشة تعالج الإشارتين | العميل يدفع عربوناً لنا والباقي نقداً للسائق؛ هذا قلب المرحلة ٧ لا حالة حافّة |

## ٣) Whitelabel: صفر نصوص علامة في الكود

| القاعدة | السبب في سطر |
|---|---|
| كل قيمة خاصة بالعلامة (اسم، شعار، ألوان، هاتف، واتساب، سوشيال) تمر عبر `lib/site-config.ts` ← جدول `site_settings` | النسخة الثانية تُطلق بتعديل بيانات لا بتعديل كود (المرحلة ١٤) |
| القيم في `site-config.ts` **fallback دائم** لا مصدر — تبقى كذلك حتى بعد ربط القاعدة | حتى لا يتحول الافتراضي بمرور الوقت إلى مصدر حقيقة موازٍ |
| ممنوع كتابة اسم أو لون أو رقم في مكوّن — حتى في نص placeholder | تدقيق «صفر نصوص ثابتة» بند إغلاق في المرحلة ١٤ |
| **الأسرار في البيئة، الوجهات في اللوحة**: توكن البوت ومفتاح البريد في `.env.local`؛ معرّف محادثة تليجرام وبريد الفريق في `site_settings` (`lib/site-config.ts:44-55`) | ما ليس سرّاً يجب أن يغيّره المالك بلا مبرمج؛ وما هو سرّ لا يُخزَّن في قاعدة تُقرأ من الواجهة |
| نسخة واحدة لكل علامة (مشروع Supabase + Vercel + دومين مستقل) — **لا `tenant_id`** | عزل تام: خطأ RLS واحد لا يسرّب بيانات علامة إلى أخرى |

## ٤) الشكل القياسي لأي Server Action

المرجع الحي: `app/admin/pricing/actions.ts` — أربع خطوات بالترتيب، بلا تخطٍّ.

```ts
"use server";
const url = (qs: string) => `/admin/pricing?${qs}`;

export async function savePricingSettings(formData: FormData) {
  // (١) فحص البيئة أولاً
  const supabase = await createServerSupabase();
  if (!supabase) redirect(url("error=env"));

  // (٢) التحقق من المدخلات ← خروج فوري برمز واضح
  const peakPercent = num(formData, "peak_percent");
  if (peakPercent === null || peakPercent < 0) redirect(url("error=percent"));

  // (٣) الكتابة مع .select() وفحص صفر صفوف
  const res = await supabase.from("pricing_settings").update(patch).eq("id", id).select();
  if (res.error || !res.data || res.data.length === 0) redirect(url("error=save"));

  // (٤) إبطال الكاش ثم إعادة توجيه بنجاح
  revalidatePath("/", "layout");
  redirect(url("saved=1"));
}
```

| الخطوة | السبب في سطر |
|---|---|
| فحص `!supabase` قبل أي شيء | بلا متغيرات البيئة يرجع العميل `null`، والاستدعاء عليه ينفجر بخطأ غامض بدل رسالة مفهومة |
| `.select()` بعد كل `update`/`delete` وفحص `length === 0` | **أخطر فخ في Supabase**: RLS ترفض الكتابة بلا خطأ — «نجاح» مع صفر صفوف (`supabase/README.md` ← «قائمة التحقق» البند ٢) |
| `revalidatePath` قبل التوجيه | تعديل من اللوحة يجب أن يظهر في الموقع فوراً (وعد اعتبار ٢ في الرؤية) |
| `redirect()` في نهاية **كل** مسار: نجاحاً وفشلاً | اعتبار ٨: لا يبقى المستخدم على شاشة النموذج بعد الحفظ؛ والنتيجة رابط قابل للمشاركة والتحديث بلا حالة عميل |
| الحالة تسافر في **رموز query string** (`?saved=1`, `?error=env`, `?error=marginmig`) والصفحة تترجمها إلى نص عربي | لا حالة في الذاكرة، ولا `useState` لرسالة خطأ، ويعمل مع JS معطّل |
| رمز خطأ مستقل لكل سبب (`percent` / `margin` / `marginmig` / `save` / `coords` / `coordpair`) | رسالة واحدة عامة تُخفي أي الحقول أخطأ |

## ٦) الترحيلات (migrations)

| القاعدة | السبب في سطر |
|---|---|
| **قابلة لإعادة التنفيذ**: `create table if not exists` · `create or replace function` · `drop policy if exists` قبل كل `create policy` · كتل `do $$ ... $$` للفحص المشروط | الملف قد يُعاد على قاعدة نصف مهاجَرة، وعلى نسخة Whitelabel جديدة، وعلى قاعدة بدر معاً |
| **ترويسة عربية** أعلى كل ملف تشرح ماذا ولماذا، وملفات التصليب ترقّم العيوب التي تعالجها (`0021_payments_hardening.sql:1-18`) | الترحيل هو السجل الوحيد لسبب القرار بعد اختفاء المحادثة |
| **كتلة `revoke` ثم `grant`** في كل ترحيل ينشئ جداول (`0005_pricing.sql:109-133`, `0007_booking.sql:1259-1275`) | Supabase تمنح `anon` صلاحيات واسعة افتراضياً على الجداول الجديدة — منها `TRUNCATE` **وهي لا تخضع لـ RLS إطلاقاً**. سطور `revoke` حمّالة: حذفها يفتح الجداول |
| الأقل صلاحية: جدولا الكاش بلا أي `grant` للأدوار العامة، والدوال الحساسة لـ `service_role` وحده | المرحلة ٤: `create_booking` كانت متاحة لـ `anon` وتقبل المسافة كمُدخل — الحماية كانت عُرفاً لا حاجزاً |
| ترقيم متسلسل بأربع خانات ولا يُعدَّل ملف مطبَّق أبداً — التصحيح ترحيل جديد | `schema_migrations` يتتبع بالاسم؛ تعديل ملف مطبَّق لا يصل إلى أي نسخة أخرى |
| `comment on table/function` بالعربية للقرارات الخطرة | التعليق يسافر مع القاعدة إلى كل نسخة، والملف قد لا يُقرأ |

## ٧) كل دالة `security definer` تثبّت `search_path`

```sql
create or replace function public.accept_offer(p_offer uuid)
returns ... language plpgsql
security definer
set search_path = ''      -- ← إلزامي
as $$ ... $$;
```

| القاعدة | السبب في سطر |
|---|---|
| `set search_path = ''` (فارغ) في كل دالة definer — والنتيجة أن **كل مرجع يُكتب مؤهلاً**: `public.bookings`, `auth.users` | بدونه يستطيع مستخدم بصلاحية إنشاء schema أن يزرع جدولاً يخطف اسم جدولك داخل دالة تعمل بصلاحيات المالك |
| قبل كل `grant execute` اسأل: ماذا يرى **متعهد مسجَّل الدخول**؟ | كل متعهد مستخدم `authenticated`؛ المرحلة ٥ منحت `coverage_matches` (definer يتجاوز RLS) لـ `authenticated` فانكشفت قوائم كل المنافسين |
| الأمان بنيوي لا انضباطي: `quote_public()` **لا تحمل أعمدة التكلفة أصلاً**، و`portal_offers()` لا تحمل أعمدة العميل | ما لا يوجد في نوع الإرجاع لا يُسرَّب بخطأ في الواجهة |

## ٨) الاختبارات

| القاعدة | السبب في سطر |
|---|---|
| الاختبارات SQL في `supabase/tests/*.sql` وتعمل **على القاعدة الحية** — لا إطار JS ولا قاعدة اختبار منفصلة | ما يُختبر هو دوال Postgres نفسها بصلاحياتها الحقيقية، وهي المنطق كله |
| **تنظّف نفسها في البداية والنهاية معاً** بمعرّفات ثابتة (`d0/d1/d2…`) ووسوم (`BOOKING_TESTS_FIXTURE`) | التنظيف الأولي يعني أن تشغيلاً منهاراً في المنتصف لا يمنع التالي |
| **بيانات fixture فقط، لا بيانات حقيقية** — مقاطع «بلا تغطية» بإحداثيات صحراوية | مجموعات استعملت مسار القاهرة–الإسكندرية الحقيقي، فصارت تفشل بمجرد وجود متعهد يغطيه — أي **تفشل لأن المشروع نجح** |
| التوقعات تُشتق من نفس مدخلات الكود المُختبَر لا من أرقام محفورة | تغيير التعريفة أو نسبة الهامش من اللوحة يجب ألا يُسقط الاختبارات |
| اسأل عن كل تأكيد: **ماذا يثبت فعلاً؟** | اختبار في المرحلة ٥ أكّد أن المنحة المفرطة **يجب أن توجد**، وآخر في المرحلة ٦ أكّد تغيير حالة لا يفعل شيئاً — الاختبار ثبّت العيب بوصفه عقداً |
| النجاح = طباعة `ALL PASSED`، والفشل exception عربية فيها المتوقع والفعلي | مخرجات psql تُقرأ بالعين لا بمُجمِّع تقارير |

## ١٠) النشر — و`README.md` جزءٌ منه لا خطوةٌ بعده

**قرار بدر 2026-08-15، ملزم من النشرة التالية:** لا يُنشَر إصدارٌ قبل أن
يُحدَّث `README.md` ويُدفَع معه.

**والترتيب `README ← كمّة ← دفع ← نشر`، لا العكس.** المستودع واجهة المشروع لمن
لا يفتح الكود، والنشرُ يغيّر ما يعمل فعلاً؛ فتحديثٌ لاحق يترك نافذةً — قد تطول —
يصف فيها GitHub نسخةً غير المنشورة. وهذا الترتيب يجعلهما متطابقين **لحظة** النشر.

| البند في `README` | متى يتغيّر |
|---|---|
| شارتا `migrations-N` و`SQL suites-N` | مع كل هجرة أو مجموعة اختبار |
| «الترحيلات الـ N … إلى `<آخر ملف>`» | مع كل هجرة |
| جدول «ما الذي يعمل اليوم» | حين يشحن سطحٌ جديد أو تتغيّر حالة مرحلة |
| الملخص الإنجليزي | يحمل العددين نفسيهما — **يُنسى عادةً** |

والتحقق أمرٌ واحد يقارن الواقع بالمكتوب:

```bash
echo "الواقع: هجرات=$(ls supabase/migrations/*.sql | wc -l) مجموعات=$(ls supabase/tests/*.sql | wc -l)"; grep -oE "migrations-[0-9]+|suites-[0-9]+" README.md
```

⚠ **ولا يُكتفى بالأرقام.** رقمٌ صحيح في ملفٍ يصف ميزةً لم تعد تعمل أسوأ من رقم
قديم: الأرقام تُقاس والوصف يُقرأ. وسبقت هذه القاعدةَ حادثةٌ حقيقية — كان
`README` يقول «لم يُنشر منها شيء بعد» والمنصة تعمل على دومينها.

📌 وخطوات النشر نفسها وسكربتها في [`docs/VPS.md`](../docs/VPS.md) §١٢، وفيها
القاعدة نفسها مكتوبة عند نقطة التنفيذ.

> أعمى أمام ١١١ هجرة و٣٩ مجموعة و٦٠ قراراً، فيقرأ خمس وثائق ثم **يُعيد قياس
> نفس الأربعين حقيقة** المكتوبة في بريفه — لأن رقماً بلا الأمر الذي أنتجه لا
> يُصدَّق، **وحقُّه ألّا يصدّقه**.
>
> فالقواعد الأربع أدناه ليست أسلوباً مفضَّلاً؛ كلٌّ منها حادثةٌ وقعت وثمنٌ دُفع.

### ١١أ) 🔴 البُناة لا يشغّلون البوابة الكاملة — المتحقّق التسلسلي وحده يقيس

| القاعدة | السبب في سطر |
|---|---|
| **البَاني يشغّل `npx tsc --noEmit` على عمله وحده** — ولا `next build` ولا `db:test` | قِيس **ثلاث مرات في أسبوع واحد**: بوابةُ بانٍ أُبطلت بكتابةِ وكلاء آخرين أثناء جريانها، فأنتجت **صفراً** ودفعت `next build` كاملاً و`db:test` كاملاً |
| **البوابة تُقاس مرةً واحدة، في النهاية، على شجرةٍ ساكنة** | ‏`STANDING-ORDERS` §٢هـ: «ثالثٌ قاس بوابةً بينما الشجرة تتحرك تحته فكتب تقريراً بائتاً عند وصوله» |
| **`db:test` مَورِدٌ تسلسليّ** على **قاعدةٍ حيّةٍ واحدة** — لا نسخة اختبار | جولتان متزامنتان تتنازعان الصفوف نفسها، وبوّابةُ التسرّب في `scripts/db-test.mjs` تحمرّ على عملِ الآخر لا على عملك |
| وإن اضطررتَ إليه وسط تزاحم: **أعِد المجموعة الساقطة وحدها** (`node scripts/db-test.mjs <اسم>`) **وقُل صراحةً** أنك تشتبه في تزاحم | الفارق بين «عيبٌ في عملي» و«جارٌ يكتب» يُحسم بإعادةٍ منفردة لا بتخمين |

📌 والأداة التي تنفّذ هذا التدرّج: `node scripts/state-snapshot.mjs` يقيس `tsc`
وحده افتراضياً، و`--gate` وحده يضيف `next build` و`db:test`.

### ١١ب) أرقام الهجرات تُسنَد في البريف، ولا تُشتقّ أبداً

| القاعدة | السبب في سطر |
|---|---|
| **رقم هجرتك مكتوبٌ في مهمّتك.** خذه ولا تأخذ غيره | اشتقّ وكيلان «الرقم الحرّ التالي» كلٌّ على حدة فأخذا **`0100`** معاً ⇒ جسمُ هجرةٍ جرى مرتين، وقضى المالك يوماً بدفترٍ يخالف القرص |
| **الرقم الحرّ في أي وثيقة معلومةٌ لا إذن** — بما فيه `docs/STATE.md` و`facts.mjs` | الوثيقة تصف لحظةَ قراءتها؛ ووكيلٌ آخر قد يكون أخذ الرقم قبل ثانية |
| **والعدد ≠ أعلى رقم** ما دامت فجوةُ `0090`/`0091` قائمة — **ولا تُملأ** | الاشتقاق بالعدّ يعطي رقماً مستعمَلاً سلفاً |
| 🔴 **ولا تُملأ فجوةٌ جديدة أبداً** — الفجوة قد تكون رقماً **أُسنِد لوكيلٍ لم ينزل ملفُّه بعد** | مقيسٌ 2026-08-18: ظهرت `0115` و`0116` فجوتين وسط موجةٍ جارية بينما `0117` على القرص. فمن «ملأ الفراغ» أخذ رقمَ جارٍ يعمل الآن |
| ومن لا رقم في بريفه: **يطلبه ولا يخترعه** | تصادمُ رقمين لا يُكتشف إلا بعد التطبيق، وحينها يكون الجسم قد جرى |

### ١١ج) المراجعة والنموذج والجهد تُدرَّج بالمخاطرة

`STANDING-ORDERS` §٢د تدرّج **المراجعة**؛ وهذه تمدّها إلى **من يُشغَّل وبأي جهد**:

| المادة | النموذج والجهد | المراجعة |
|---|---|---|
| **مال · صلاحيات · بيانات عميل · هجرات** | الأعلى المتاح، بلا تفاوض | عدائية كاملة |
| بنيةٌ أو منطقٌ جديد | متوسط | مراجعة واحدة |
| واجهة وألوان ونصوص | خفيف | **نظرةٌ حيّة في المتصفح وحدها** |
| وثائق · إعدادات · هروبُ محرفٍ أو `NUL` · إعادةُ تسمية | الأخف | لا شيء |

⚠ **والهدر ليس في المبدأ بل في التسوية بالأعلى:** رُوجع تغييرُ ألوانٍ بصرامة
مراجعةِ عمولة الدفع. وفي اليوم نفسه أمسكت المراجعة العدائية **خمس حصائل حرجة**،
**ثلاثٌ منها قالت تقارير البُناة إنها سليمة** — فالصرامة تُنفَق حيث تُمسك، لا
بالتساوي.

### ١١د) الوحدات الأصغر تنجو من الأعطال

| القاعدة | السبب في سطر |
|---|---|
| **مهمّةٌ واحدة لكل وكيل، بملفّاتٍ مسمّاة، وحصيلةٍ تُقاس وحدها** | ماتت موجةٌ من **ستة وكلاء معاً** فضاع **٥٠٦٬٠٠٠ رمز** دفعةً واحدة؛ والعطل نفسه موزَّعاً على وحدات أصغر يُضيّع كسراً منه |
| **اكتب على القرص قبل أن يمتلئ السياق لا بعده** (`STANDING-ORDERS` §٤) | ما لم يُكتب يموت مع الموجة، وما كُتب يستأنفه غيرك |
| **بريفٌ يسمّي ملفاتك، وما خرج عنها يُبلَّغ ولا يُحرَّر** | وكيلان على ملفٍّ واحد **يمحو أحدهما الآخر بلا خطأ يظهر** — وقع فعلاً في 2026-08-17 |

### ١١هـ) المرجع يُولَّد ولا يُستطلَع
